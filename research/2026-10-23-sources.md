## Recommended lead — agent infrastructure becomes a product category

- **Google Cloud, 22 October 2026:** [Introducing Agent Compute Engine and expanded agent governance](https://cloud.google.com/blog/topics/ai-infrastructure/introducing-agent-compute-engine-and-expanded-agent-governance)
  - Google says **Agent Compute Engine** already powers Gemini for work-agent tasks and will enter preview “in the coming months.” This is a company announcement, not independent performance evidence.
  - The service gives each agent a hardware-isolated microVM; Google says it uses copy-on-write memory sharing across a single OS template, pauses idle VMs and resumes them from snapshots.
  - Google says each microVM has its own identity, receives short-lived credentials, and has a Hyperdisk for persisted execution state. It also describes governance controls spanning an Agent Gateway, Agent Registry, policy enforcement, observability and auditability.
  - **Suggested angle:** “The agent race moves below the chat window.” The product implication is a clearer separation between an agent’s disposable execution environment, durable task state, and authority to touch enterprise systems. Do not describe the service as generally available.
  - **Builder’s Notebook fit:** *execution environments as an interface contract*. Mechanism: task request → isolated runtime + short-lived identity → tool execution/state persistence → auditable outcome. This does not duplicate the recent issue’s temporal-policy or hurdle-rate concept.
