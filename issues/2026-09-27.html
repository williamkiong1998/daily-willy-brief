☕ Cold Open

The important AI product shift this week is not another capability benchmark. It is the slow conversion of invisible system activity—who got in, what changed, where an agent acted—into something a person can inspect without opening a support ticket.

Sunday, 27 September 2026 · Kuala Lumpur

The Lead

Security becomes a product surface

ChatGPT has introduced Security history, a view of sign-ins, sign-outs and changes to MFA, passkeys and other security settings. The feature includes time, location and device details, though the release notes warn that some details may be approximate or unavailable. That sounds prosaic, which is precisely the point. A security control that cannot be reviewed by the account holder is a rule trapped in infrastructure. As more products gain connectors, persistent memory and tool access, the human needs a readable answer to a mundane but consequential question: what happened while I was not looking? An activity log is not a cure for a bad permission model. It is the receipt that lets a user challenge one.

Why it matters: trust in agentic software will be built through legible evidence and recovery paths, not increasingly confident permission dialogs.
The Takeaway
The interface for AI trust is increasingly a timeline, not a toggle. Teams should design the trail, its owner and its escalation route before they make a workflow autonomous; otherwise observability arrives only after the first uncomfortable incident.
🤖 AI & Tech
The hard work is making AI behaviour inspectable
01
OpenAI fixed an image-encoding bug in GPT-6 Sol and GPT-6 Luna that degraded image understanding in API and Codex visual tasks. Its practical instruction is unusually sound: rerun affected evaluations. Multimodal quality is not a static attribute; a quiet encoder fault can alter what an agent “saw,” and a model upgrade does not automatically validate the workflow wrapped around it.
02
Google Research published work on automating coherent long-form video generation. The research milestone is less about making longer clips than preserving intention across time. Product teams face the same systems problem in a smaller costume: a useful agent must retain a plan, recover from divergence and show the user where coherence was lost.
03
Google says its agentic pre-submit scanning now checks every code change across hundreds of millions of lines and prevents hundreds of vulnerabilities monthly. That is a company claim, not an independent benchmark. Still, the architecture is the signal: put agents upstream of irreversible release, where findings can be reviewed, rather than asking them to clean up production consequences later.

🧠 Builder’s Notebook
Event sourcing: make the system remember what it did
Intuition: event sourcing means retaining the sequence of meaningful changes, not merely the latest state. A bank balance tells you what is true; a statement tells you how it became true. For an AI product, that distinction separates “the agent sent an email” from a reviewable account of the instruction, approval, tool call and result.

Mechanism:
action → immutable event → actor + context → queryable timeline → review, rollback or escalation
This is not a call to put every log in a blockchain. It is a design constraint: events need stable names, a trustworthy order, scoped retention and a deliberate reader. Security history is a user-facing slice of that architecture. Without the underlying events, a friendly timeline becomes theatre; without the timeline, good infrastructure hides its evidence from the person bearing the risk.

Try this (20 min): pick one automation that touches customer or internal data. Draw five events: request received, data read, recommendation generated, approval given, action executed. For each, specify actor, timestamp, object, permission and undo path. If a later reviewer cannot reconstruct why the action happened, add the missing event before adding more autonomy.
