☕ Cold Open

The AI race is acquiring a useful second question: not merely who has the best model, but who gets to run it where—and under whose operating discipline. Today’s thread is portable capability meeting very unportable responsibility.

Monday, 5 October 2026 · Kuala Lumpur

The Lead

The model leaves the building. The operating model follows.

Aleph Alpha released Kolibri-1, a German-English open-weight model under the Apache 2.0 licence. Its model card lists 78.1 billion total parameters but only 3.46 billion active per token, plus reasoning mode, tool calling and a stated maximum context of 1,048,576 tokens. Those are vendor technical disclosures, not an independent performance verdict. The more consequential fact is deployability: the weights can be run through an OpenAI-compatible server rather than only consumed through one vendor’s hosted product. That changes the buyer’s menu from “pick a model” to “own an inference stack, data boundary and update cadence.” Why it matters: sovereignty is not a checkbox on a procurement form; it is an operating capability with hardware, security and evaluation costs attached.
THE TAKEAWAY
Open weights remove one kind of dependency and create three others: serving economics, model change control and accountability for the system’s behaviour. The useful question is not “can we self-host?” but “can we run this with evidence when it matters?”

🧠 Builder’s Notebook
Sparse activation: make the expensive capability conditional
Intuition: a mixture-of-experts model is a restaurant that does not summon every chef for every plate. A router picks the few specialists likely to help, so the kitchen can offer a large menu without spending a banquet’s effort on a coffee order.

Mechanism:
request → router selects specialists → small active path → answer → latency and cost budget
Kolibri-1 reports 78.1B total parameters but 3.46B active per token. The saving is real only at inference time; the full model still needs memory, deployment capacity and a route that reliably chooses useful experts. That is why “cheaper per token” never equals “cheap system.”

Try this (20 min): take one expensive AI workflow and list its requests by complexity: lookup, transform, judgement. Route the first two to a cheaper model or deterministic tool; reserve the stronger model for judgement. Then log the fallback rate. You have designed a product-level mixture of experts before touching model weights.
